04
№ 04  —  DIENSTE IM DETAIL

Was läuft, woraus, mit welchen Volumes.

Prometheus

  • Compose: configs/monitoring/prometheus/docker-compose.yml
  • Image: prom/prometheus:latest (kein Pin)
  • Network: network_mode: host — :9090
  • Volumes: prometheus.yml + alert-rules.yml read-only, Named Volume tsdb → /prometheus
  • Retention: 15d / 2GB
  • Scrape: Jobs node_exporter (cachyos+vps) und prometheus (self)
  • Alert-Rules: TargetDown, HighCpuUsage, LowMemory, DiskFillingUp
  • Alertmanager-Ziel: 100.92.62.9:9093

Grafana

  • Compose: configs/monitoring/grafana/docker-compose.yml
  • Image: grafana/grafana:latest
  • Bind: GF_SERVER_HTTP_PORT=3001 (Default 3000 belegt durch AGH)
  • Volumes: Named Volume grafana-data, ./provisioning + ./dashboards read-only
  • Datasources (provisioned): Prometheus (UID prometheus, default), Loki (UID loki) — deleteDatasources räumt Lern-Phase-Reste weg
  • Dashboard-Provider: File-Watcher, Folder Homelab, Reload alle 30 s

Loki + Promtail

  • Images: grafana/loki:latest, grafana/promtail:latest, beide network_mode: host
  • Loki-Storage: Filesystem, Named Volume loki-data → /loki, Schema v13/tsdb, 24 h Index-Periode
  • Retention: 168h (7 Tage), reject_old_samples: false
  • Limits: ingestion_rate_mb: 16, max_global_streams_per_user: 5000
  • Promtail cachyos: Jobs journal (Labels host=cachyos) + docker (Socket-Discovery)
  • Promtail server-ops: Push-Ziel http://100.95.132.54:3100/loki/api/v1/push, Force-Label host=vps

Alertmanager

  • Host: server-ops, network_mode: host, :9093, user: "0:0"
  • Template: alertmanager.yml.tpl, gerendert via envsubst aus .secrets.env nach /tmp/alertmanager.yml (chmod 600)
  • Route: single Receiver all-channels, group_by: [alertname, host], repeat_interval: 4h, Inhibit critical → warning
  • ntfy: https://ntfy.sh/${NTFY_TOPIC}, send_resolved: true — roher JSON-Push, hübsche Titel + Priority-Mapping fehlen (Loose End)
  • Telegram: HTML-Template mit Status/Host/Severity/Summary, send_resolved: true
  • Priority-Routing (geplant, nicht im Repo): critical → high+rotating_light, warning → default, resolved → low+check_mark — Teil der offenen ntfy-Bridge-Arbeit

node_exporter und ntopng

  • node_exporter: prom/node-exporter:latest, network_mode: host, pid: host, /proc//sys// ro nach /host/.... Identisch auf beiden Hosts.
  • ntopng: ntop/ntopng:latest, Caps NET_ADMIN + NET_RAW, Sniffer auf wlan0, Web-UI :3002. Sieht keinen LAN-internen Cross-Talk (kein SPAN auf FritzBox).

Backrest (restic-UI)

  • Image: garethgeorge/backrest:latest, Version 1.13.0 auf beiden Hosts (Multihost-Voraussetzung)
  • Port: 100.95.132.54:9898:9898 — explizit auf Tailnet-IP gebunden
  • Multihost-Pairing: cachyos = Server, server-ops = Client, beide Repos in einer UI

  • server-ops: homelab-backup-vps.{sh,service,timer}, OnCalendar=*-*-* 03:30:00
  • Status: Backrest ist Primary, Timer historisch/Backup-of-Backup. TBD: ob aktuell auf den Hosts aktiv (systemctl list-timers)

DNS / AdGuard Home

  • Primary (cachyos): Compose unter configs/agh-cachyos/, Image adguard/adguardhome:latest, Bridge-Network, Ports 53/tcp, 53/udp, 3000/tcp. Host-Bind-Mounts /home/alex/adguard/{conf,work}. Compose-Migration auf Host steht aus (aktueller Container ist docker run).
  • Fallback (server-ops): bare-metal/docker run, Bind-Mounts /home/admin/agh/{conf,work}. Auf demselben Host läuft agh-sync als Sync-Origin.
  • Filterlisten: AdGuard DNS filter, AdAway, OISD Big, HaGeZi Pro, Steven Black (aus VPS-Sync)
  • Upstreams: cachyos → Quad9 DoH (https://dns10.quad9.net/dns-query), Bootstrap 9.9.9.10. server-ops → Quad9 DoT (tls://dns.quad9.net) + Cloudflare DoT, Bootstrap 9.9.9.9, 1.1.1.1.
  • Encrypted DNS Serving: DoT/DoH/DoQ-Ports im Compose nur als Kommentar — nicht aktiv, AGH dient lokal Plain DNS auf :53
  • DoT-Outbound-Lernpunkt: wiederholte Timeouts zu Quad9/Cloudflare in Loki sichtbar — Diagnose offen (vermutlich IPv6-Routing oder MTU)

agh-sync

  • Host: server-ops, Image ghcr.io/bakito/adguardhome-sync:latest
  • Schedule: CRON=*/5 * * * *
  • Synchronisiert: Filter, Clients, DNS-Server-Config, DNS-Rewrites
  • Bleibt lokal: General-Settings, Query-Log-Config, Stats-Config, Services
  • Querylog → Loki: NICHT verdrahtet. Loose End — zweiter Promtail-Job auf /opt/adguardhome/work/data/querylog.json fehlt

Netzwerk-Flow / ntopng

  • Sniffer-Interface: wlan0 (cachyos)
  • Sichtbar: eigener WLAN-Verkehr, evtl. Multicast/Broadcast
  • NICHT sichtbar: LAN-internen Cross-Talk (IoT ↔ Apple TV ↔ Drucker) — FritzBox 7520 hat keinen SPAN. Andere WLAN-Clients ebenfalls nicht (WLAN-Treiber zeigt im Promiscuous-Modus oft nur eigenen Traffic).
  • Workaround: Managed Switch mit Port-Mirror (z. B. Mikrotik CRS112) — nicht angeschafft.

№ 06  —  SECRETS-STRATEGIE

Wo Tokens liegen, was nicht im Repo landet.

  • .env-Files: chmod 600, gitignored via .env, .env.* (Ausnahme .env.example)
  • Templates im Repo: configs/agh-sync/.env.example, Alertmanager alertmanager.yml.tpl mit Platzhaltern (${NTFY_TOPIC}, ${TELEGRAM_BOT_TOKEN}, ${TELEGRAM_CHAT_ID})
  • Restic-Passphrasen: NordPass ist Single Source of Truth. Klartext-Files mit shred -uz entsorgt (2026-05-21)
  • Google-Konto-Login (rclone-OAuth): NordPass
  • Grafana-Admin-Passwort: bei Erst-Login geändert, neuer Wert in NordPass — Default admin/admin im Compose ist nur Bootstrap
  • AGH-Web-UI-Passwörter: beide Instanzen eigene Logins, NordPass
  • Token-Validity-Falle: gdrive-OAuth-App auf „In Production" — kein 7-Tage-Token-Tod
