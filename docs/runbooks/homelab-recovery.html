Homelab
Recovery.

Operative Schritt-Anleitung für den Tag, an dem entweder die cachyos-Festplatte stirbt oder der Contabo-VPS hinter server-ops verloren geht. Audience: Alex selbst, drei Uhr nachts, ohne Geduld für Pädagogik.

01
№ 01  —  SCOPE

Was hier drin steht / was nicht.

Dieses Dokument ist die operative Schritt-Anleitung für den Tag, an dem entweder die cachyos-Festplatte stirbt oder der Contabo-VPS hinter server-ops verloren geht.

Der IST-Stand der Maschinen wird in docs/SETUP.md gepflegt, der geplante Soll-Stack steht in Monitoring-Stack-Design und Tailnet-Adblock-Design.

Wenn ein Schritt mit TBD markiert ist, ist die Lücke nicht aus dem Repo belegbar — bitte vor dem ersten Trockenlauf füllen.

02
№ 02  —  VORAUSSETZUNGEN

Sechs Dinge außerhalb der kaputten Maschine.

Bevor irgendein Recovery-Schritt anfängt: diese sechs Ressourcen müssen erreichbar sein. Sonst Henne-Ei.

#RessourceQuelle / PfadAnmerkung
1Restic-Repogdrive:homelab-backups-restic/<host> via rclonePro Host eigener Pfad
2Restic-PassphraseBitwarden „Homelab · restic · <host>"Niemals im Repo, niemals im Chat
3rclone-OAuth / Google-LoginBitwarden „Google · <gdrive-account>"OAuth-App temporal-state-497009-n0; 7-Tage-Falle, siehe §9
4Tailscale-Auth-KeyAdmin Console → Settings → Keysreusable, pre-approved, tag:home
5Repo-Clonegit@github.com:arn0ld87/homelab.gitAuf einem Drittgerät klonen, nicht auf der kaputten Maschine
6VPS-Provisioning-ZugangContabo-Account-LoginBitwarden „Contabo · root"

.env-Files mit AGH-/Alertmanager-/Sync-Secrets liegen ebenfalls in Bitwarden (Eintrag pro Stack). Sie sind nicht im Restic-Backup — darum hier explizit aufgelistet.

03
№ 03  —  SZENARIO A

cachyos-Desktop neu aufsetzen.

Häufiger Fall. 90–120 min realistisch.

cachyos hält Prometheus, Grafana, Loki, ntopng, node_exporter, AdGuard-Home-Replica, Backrest-Server und das Restic-Repo gegen Google Drive.

CachyOS-Installation

ISO booten, Installation per cachyos-installer. Filesystem-Layout, Disk-Encryption (LUKS), Bootloader-Wahl: TBD — bitte aus früherem Setup-Doku ergänzen.

Basis-Pakete

bash
sudo pacman -Syu --noconfirm
sudo pacman -S --noconfirm restic rclone docker docker-compose git curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER  # neu einloggen danach

Tailscale installieren + joinen

bash
sudo pacman -S --noconfirm tailscale
sudo systemctl enable --now tailscaled
sudo tailscale up \
  --hostname=cachyos \
  --authkey=${TAILSCALE_AUTHKEY} \
  --accept-dns=false
tailscale ip -4   # erwartet 100.95.132.54 (oder neu zugewiesene IP)

--accept-dns=false, damit cachyos seinen lokalen AGH-Resolver weiter selbst betreiben kann — Tailscale-MagicDNS würde sonst konkurrieren.

Repo-Clone nach ~/monitoring

bash
git clone git@github.com:arn0ld87/homelab.git ~/homelab
mkdir -p ~/monitoring
cp -a ~/homelab/configs/monitoring/* ~/monitoring/
cp -a ~/homelab/configs/agh-cachyos    ~/monitoring/agh

rclone-Remote gdrive einrichten

bash
rclone config
# n → name "gdrive" → drive → leere client_id → scope 1
# Auto-Config: y → Browser-OAuth → Token kommt zurück
# Shared Drive: n → y (confirm) → q (quit)
rclone lsd gdrive:   # sanity check

Headless? rclone authorize "drive" auf einer Maschine mit Browser, Token-Blob einspielen.

Restic-Repo öffnen + Snapshots prüfen

bash
echo -n "${RESTIC_PASSWORD}" > ~/restic-passphrase.txt
chmod 600 ~/restic-passphrase.txt
export RESTIC_REPOSITORY="rclone:gdrive:homelab-backups-restic/cachyos"
export RESTIC_PASSWORD_FILE=~/restic-passphrase.txt
restic snapshots --last 5

Fatal: wrong password → Bitwarden prüfen, kein Zeilenumbruch am Datei-Ende. already locked → §6.

Trockenlauf-Restore

bash
restic restore latest --target /tmp/restore-dryrun --dry-run \
  --include /home/alex/monitoring \
  --include /home/alex/adguard \
  --include /etc

Echter Restore

bash
restic restore latest --target /tmp/restore \
  --include /home/alex/monitoring \
  --include /home/alex/adguard \
  --include /etc \
  --include /var/lib/docker/volumes
sudo cp -a /tmp/restore/home/alex/monitoring/. ~/monitoring/
sudo cp -a /tmp/restore/home/alex/adguard      /home/alex/adguard
sudo cp -a /tmp/restore/var/lib/docker/volumes/. /var/lib/docker/volumes/

Volumes-Restore optional. Wer mit leerem TSDB starten will (sauberer Cut), lässt den volumes-Include weg.

.env-Files aus Bitwarden zurückspielen

  • ~/monitoring/agh-sync/.env — falls hier mitlaufend
  • ~/monitoring/alertmanager/.secrets.env — NTFY_TOPIC, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
  • ~/.grafana-token (chmod 600)

AdGuard-Home-Container hochfahren

bash
cd ~/monitoring/agh
docker compose up -d
docker compose logs --tail 20 adguardhome
dig @127.0.0.1 doubleclick.net +short   # erwartet 0.0.0.0

Monitoring-Stack hochziehen

bash
cd ~/monitoring/node_exporter && docker compose up -d
cd ~/monitoring/prometheus    && docker compose up -d
cd ~/monitoring/loki          && docker compose up -d   # bringt Promtail mit
cd ~/monitoring/grafana       && docker compose up -d
cd ~/monitoring/ntopng        && docker compose up -d
docker ps   # erwartet 6+ container running

Backrest-Server-Container starten

Compose: configs/monitoring/backrest/compose.yaml. Repo-Pfad in der Backrest-UI manuell wieder einhängen. Nicht gleichzeitig auf server-ops einen Backrest-Server für dasselbe Repo laufen lassen — siehe §9.

bash
cd ~/monitoring/backrest && docker compose -f compose.yaml up -d
# Web-UI: http://100.95.132.54:9898 (Tailnet only)

Verify

→ §8 Selbst-Test.

04
№ 04  —  SZENARIO B

server-ops-VPS neu aufsetzen.

AGH-Primary, Promtail/node_exporter (Push), Alertmanager, agh-sync, Backrest-Client. 45–60 min realistisch.

VPS provisionieren

Contabo Web-UI → neuer VPS, Debian 12 (LTS), IPv4 + IPv6, SSH-Key Upload. Hostname setzen: hostnamectl set-hostname server-ops.

Initial-Hardening

bash
apt update && apt -y full-upgrade
apt install -y nala ufw unattended-upgrades fail2ban
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl reload ssh
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw --force enable
dpkg-reconfigure -plow unattended-upgrades

Detail-Hardening (User admin statt root, ssh-Port-Tausch): TBD.

Tailscale

bash
curl -fsSL https://tailscale.com/install.sh | sh
# --accept-dns=false aus dem gleichen Grund wie auf cachyos (Schritt 3):
# der Host soll seinen eigenen AGH-Resolver (Primary) selbst betreiben
# und nicht via MagicDNS überschrieben werden.
tailscale up --hostname=server-ops --authkey=${TAILSCALE_AUTHKEY} --accept-dns=false
tailscale ip -4   # erwartet 100.92.62.9 oder neue IP

Docker + Compose

bash
nala install -y docker.io docker-compose-plugin git
systemctl enable --now docker
usermod -aG docker admin

Repo-Clone nach /home/admin/

bash
sudo -u admin -i
git clone git@github.com:arn0ld87/homelab.git ~/homelab
mkdir -p ~/agh ~/agh-sync ~/monitoring
cp ~/homelab/configs/agh-sync/docker-compose.yml ~/agh-sync/
cp -a ~/homelab/configs/monitoring/vps-agents/. ~/monitoring/
cp -a ~/homelab/configs/monitoring/alertmanager ~/monitoring/alertmanager

Eigene Compose-Datei für VPS-AGH (agh-primary): aus Journal 2026-05-20 nachbauen, oder TBD, sobald sie unter configs/ versioniert ist.

.env-Files zurückspielen

  • ~/agh/.env mit TAILSCALE_IP_VPS=100.92.62.9
  • ~/agh-sync/.env mit ORIGIN_* und REPLICA1_* (Template oben in configs/agh-sync/docker-compose.yml)
  • ~/monitoring/alertmanager/.secrets.env
  • chmod 600 auf alle drei

node_exporter + Promtail starten

bash
cd ~/monitoring/node_exporter && docker compose up -d
cd ~/monitoring/promtail      && docker compose up -d
curl -s http://localhost:9100/metrics | head -5

Verify auf cachyos: Prometheus-UI Status → Targets muss server-ops:9100 als up zeigen.

Alertmanager starten

bash
cd ~/monitoring/alertmanager && docker compose up -d
curl -s http://localhost:9093/-/healthy

Bridge alertmanager-ntfy für lesbare Titel: TBD (loose end vom 2026-05-21).

Backrest-Client starten

server-ops ist Backrest-Multihost-Client; die Server-Rolle liegt auf cachyos. Compose für reinen Client-Mode: TBD — aktuell nur die Server-Variante compose.yaml im Repo. Pragmatisch: gleichen Compose nehmen, UI gegen gdrive:homelab-backups-restic/vps verbinden, Port 9898 nicht via Tailscale exponieren.

AGH-Primary starten

bash
# Passphrase aus Bitwarden-Eintrag "Homelab · restic · server-ops"
# in lokale Datei mit chmod 600. Niemals committen.
echo -n "${RESTIC_PASSWORD}" > ~/restic-passphrase.txt
chmod 600 ~/restic-passphrase.txt

sudo cp -a /tmp/restore/home/admin/agh/. /home/admin/agh/
cd /home/admin/agh && docker compose up -d

Nur ein Service stirbt.

Kein Total-Restore, nur Container re-create. Reihenfolge egal, Repo-Zustand reicht.

ServiceHostRecovery-Befehl
Prometheuscachyoscd ~/monitoring/prometheus && docker compose up -d --force-recreate
Grafanacachyoscd ~/monitoring/grafana && docker compose up -d --force-recreate
Loki + Promtailcachyoscd ~/monitoring/loki && docker compose up -d --force-recreate
ntopngcachyoscd ~/monitoring/ntopng && docker compose up -d --force-recreate
node_exporterbeidecd ~/monitoring/node_exporter && docker compose up -d --force-recreate

06
№ 06  —  RESTIC-RESTORE-DETAIL

Single Source of Truth: Restic-Binary.

Diese Befehle stammen aus configs/monitoring/backrest/DISASTER-RECOVERY.md. Funktioniert auf jedem System mit Restic-Binary, ohne Backrest-UI.

bash
export RESTIC_REPOSITORY="rclone:gdrive:homelab-backups-restic/<host>"
export RESTIC_PASSWORD_FILE=~/restic-passphrase.txt

restic snapshots --last 10
restic restore latest --target /tmp/restore-dryrun --dry-run
restic restore latest --target /tmp/restore --include /home/alex/monitoring
restic restore <snap-id> --target /tmp/restore
restic check

Typische Fehlermodi

  • Fatal: wrong password → Passphrase falsch. Bitwarden „Homelab · restic · <host>". Kein Trailing-Newline.
  • repository is already locked → Stale Lock. restic unlock bei eigenem Lock, restic unlock --remove-all nur wenn keine andere Instanz parallel zugreift.
  • gdrive-Quota / App not verified → rclone config reconnect gdrive: oder OAuth-App auf „In Production" schieben.
07
№ 07  —  TAILSCALE-ACLs

Wenn die ACL-Datei selbst weg ist.

  1. Login auf https://login.tailscale.com → Admin Console → Access Controls.
  2. ACL-JSON-Backup aus Bitwarden „Tailscale · ACL" einfügen, Save, Test.
  3. Kein Backup? Minimal-Set, das den Recovery freischaltet:
json
{
  "tagOwners": {
    "tag:home": ["autogroup:admin"]
  },
  "acls": [
    { "action": "accept", "src": ["tag:home"], "dst": ["tag:home:*"] }
  ],
  "ssh": [
    { "action": "accept", "src": ["autogroup:admin"], "dst": ["tag:home"], "users": ["root", "alex", "admin"] }
  ]
}

Danach beide Hosts mit --advertise-tags=tag:home neu joinen oder tailscale set --advertise-tags=tag:home.

Subnet-Routes, exit-Nodes, Magic-DNS-Split: TBD — Detail eintragen, sobald die ACL-Datei einmal in Bitwarden archiviert ist.

09
№ 09  —  BEKANNTE FALLSTRICKE

Aus den Journals zusammengezogen.

gdrive-OAuth-Token 7-Tage-Falle

OAuth-App temporal-state-497009-n0 im Status „Testing" → Refresh-Token läuft nach 7 Tagen ab, Backups + Restore sterben mit oauth2: token expired. Fix: App auf „In Production" schieben oder Service-Account-JSON statt OAuth nutzen. Loose end aus CLAUDE.md.

CachyOS-AGH DoT-Timeouts

tls://dns.quad9.net:853 und tls://1.1.1.1:853 zeigen periodische Timeouts in Loki-Logs. Nach Reboot kurz warten, Bootstrap-DNS (9.9.9.9 / 1.1.1.1) prüfen, IPv6 checken (ping6 -c 1 dns.quad9.net).

Doppelte Prometheus-Datasource

Provisioning legt manchmal einen zweiten Auto-Eintrag an (Prometheus + prometheus). Nach Restore im Grafana-UI eine löschen — sonst leere Panels durch falsche UID.

AGH-Query-Log → Loki

Promtail liest aktuell nur stdout. Query-Log liegt in /home/alex/adguard/work/data/querylog.json und kommt erst mit dem zusätzlichen static_configs-Job rein (PR #4). Leere {container="adguardhome"}-Queries sind erwartet, kein Bug.

Backrest-Multihost-Topologie

cachyos = Server, server-ops = Client. Nicht beide gleichzeitig Backrest-Server gegen dasselbe Restic-Repo laufen lassen — Lock-Konflikte und korrupte Snapshot-Indizes. Beim Recovery alten Container hart stoppen (docker stop backrest).

AGH-Port-Default 80

Frischer AGH-Container lauscht intern wieder auf 0.0.0.0:80, Compose erwartet 3000. Nach Restore prüfen, dass http.address: 0.0.0.0:3000 im AdGuardHome.yaml steht (Stolperstein 8 aus Journal 2026-05-20).

Prometheus UID 65534

Named Volume statt Bind-Mount benutzen — bei Bind-Mount unter falschem Owner crasht der Container.

Loki rejects old samples

Nach Restore mit alten Logs: entry has timestamp too old. reject_old_samples: false in loki-config.yml ist dafür da — falls aus Restore weg, manuell setzen und Loki neu starten.

Tailscale-Override auf macOS

Vom Mac aus prüfen, ob CachyOS-AGH auf LAN-IP funktioniert: dig @192.168.178.74 direkt — scutil --dns zeigt sonst nur den Tailscale-Resolver.

10
№ 10  —  HÄUFIGKEIT

Quartals-Trockenlauf.

Einmal pro Quartal — wegwerfbare VM (libvirt / VirtualBox / Multipass), eines der Szenarien §3 oder §4 von Schritt 1 bis Verify. Erkenntnisse als Journal-Eintrag YYYY-MM-DD-recovery-dryrun-<host>.md ablegen, Soll/Ist/Lernpunkt-Schema wie alle anderen Journals.

Bei jeder strukturellen Stack-Änderung (neuer Service, neuer Host, neuer Backup-Pfad): dieses Runbook im selben PR mitaktualisieren — sonst läuft es stillschweigend tot.
