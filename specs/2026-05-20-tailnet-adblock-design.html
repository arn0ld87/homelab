№ 01  —  INFRASTRUKTUR-PLAN STAND 20. MAI 2026

Tailnet-
Werbeblocker.

DNS-basiertes Blocking für alle Geräte im Heim-LAN und auf Tailscale unterwegs. Zwei AdGuard-Home-Instanzen, VPS primär, CachyOS sekundär, synchronisiert. YouTube-Pre-Rolls sind nicht im Scope (gleicher Host wie das Video).

Version 0.1.1
Stand 20. Mai 2026
Autor Alexander Schneider
Geltungsbereich Heim-LAN + Tailnet
Lesedauer ≈ 10 Min.
01
№ 01  —  ZIEL

Was gebaut wird.

Zwei AGH-Knoten im Tailnet, eine Bedienoberfläche. Heim-Clients bekommen den DNS über die FritzBox, Mobilgeräte über Tailscale-MagicDNS.

Constraints

  • VPS-Hardening bleibt. AGH bindet nur an die Tailscale-IP, kein Port auf eth0.
  • VPS-AGH ist die einzige Bedienoberfläche. CachyOS-AGH ist Read-Only-Spiegel.
  • AGH-Query-Logs pro Client lesbar.
  • Kein NextDNS, kein Cloudflare-for-Families.

Out of Scope

  • Öffentlicher DoH-/DoT-Endpoint
  • Tailscale-Subnet-Routes ins Heim-LAN
  • Eigener rekursiver Resolver (Unbound) — Quad9 DoT reicht
  • YouTube-spezifische Maßnahmen
  • Per-Client-Familienfilter
02
№ 02  —  ARCHITEKTUR

Topologie und Datenflüsse.

Pfad Auslöser Resolver Upstream
Heim-LAN / IoT FritzBox-DHCP CachyOS-AGH (LAN-IP) Quad9 DoT
Mobil unterwegs Tailscale-App + MagicDNS VPS-AGH (Tailscale-IP) Quad9 DoT
Mobil zu Hause, Tailscale on Tailscale „Override local DNS" VPS-AGH (Tailscale-IP) Quad9 DoT

Sync: adguardhome-sync läuft als Container auf dem VPS, pollt VPS-AGH-API alle 5 Minuten und pusht Diffs an CachyOS-AGH. Manuelle Änderungen in der CachyOS-UI werden beim nächsten Lauf überschrieben.

03
№ 03  —  VPS-AGH (PRIMARY)

Tailscale-Bind, kein Port auf eth0.

Bind

Port 53 und Web-UI nur auf der Tailscale-IP, nie auf 0.0.0.0. UFW/nftables bleiben unangetastet.

YAML/home/admin/agh/docker-compose.yml
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: agh-primary
    restart: unless-stopped
    ports:
      - "${TAILSCALE_IP_VPS}:53:53/udp"
      - "${TAILSCALE_IP_VPS}:53:53/tcp"
      - "${TAILSCALE_IP_VPS}:3000:3000/tcp"
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf
    network_mode: bridge

Wenn jemand auf network_mode: host umstellt, ist Port 53 wieder auf allen Interfaces offen. Dann braucht es eine explizite UFW-Regel deny 53/udp on eth0.

Upstream

YAMLconf/AdGuardHome.yaml (excerpt)
dns:
  upstream_dns:
    - tls://dns.quad9.net
    - tls://1.1.1.1
  upstream_mode: parallel
  fastest_addr: true
  cache_size: 8388608
  cache_ttl_min: 600
  ratelimit: 0
  bootstrap_dns:
    - 9.9.9.9
    - 1.1.1.1
04
№ 04  —  CACHYOS-AGH (REPLICA)

LAN-Bind für IoT, Tailscale-Bind für mobil im Heimnetz.

Drei Bind-Adressen: LAN für IoT, Tailscale für Mobil, Loopback gegen lokale Tools, die sonst Public-Resolver verwenden würden.

YAML~/.local/share/agh/docker-compose.yml
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: agh-replica
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf

Bei network_mode: host bindet AGH selbst — Bind-Adressen werden in der AGH-Konfig festgelegt:

YAMLconf/AdGuardHome.yaml (excerpt)
dns:
  bind_hosts:
    - ${CACHYOS_LAN_IP}
    - ${TAILSCALE_IP_CACHYOS}
    - 127.0.0.1
  port: 53

Wenn systemd-resolved Port 53 belegt: DNSStubListener=no in /etc/systemd/resolved.conf, dann systemctl restart systemd-resolved.

05
№ 05  —  SYNC

adguardhome-sync auf dem VPS.

YAML/home/admin/agh-sync/docker-compose.yml
services:
  agh-sync:
    image: ghcr.io/bakito/adguardhome-sync:latest
    container_name: agh-sync
    restart: unless-stopped
    env_file: ./.env
    command: run
ENV/home/admin/agh-sync/.env (chmod 600)
ORIGIN_URL=http://${TAILSCALE_IP_VPS}:3000
ORIGIN_USERNAME=admin
ORIGIN_PASSWORD=<secret>
REPLICA1_URL=http://${TAILSCALE_IP_CACHYOS}:3000
REPLICA1_USERNAME=admin
REPLICA1_PASSWORD=<secret>
CRON=*/5 * * * *
RUN_ON_START=true
FEATURES_FILTERS=true
FEATURES_CLIENTS=true
FEATURES_DNS_SERVER_CONFIG=true
FEATURES_DNS_REWRITES=true

Vor jeder Reparatur an der CachyOS-Instanz erst agh-sync stoppen. Sonst überschreibt der nächste Lauf alles wieder.

06
№ 06  —  FRITZBOX 7520

Lokaler DNS-Server für alle DHCP-Clients.

FritzBox-Webinterface (http://fritz.box) → Heimnetz → Netzwerk → Netzwerkeinstellungen → IP-Adressen → IPv4-Konfiguration. Im Block „Heimnetz" das Feld „Lokaler DNS-Server" auf ${CACHYOS_LAN_IP} setzen.

Clients ziehen den neuen DNS erst beim nächsten DHCP-Renew. Schneller: Lease-Zeit kurzfristig auf 5 Minuten, Geräte aus und wieder ins WLAN, Lease-Zeit zurück auf 24 h.

Das Gäste-WLAN ignoriert den Eintrag — die FritzBox setzt sich dort selbst als DNS. Für Besucher meist egal. Falls eigene Geräte im Gäste-Netz hängen: Tailscale auf dem Gerät einschalten.

Verifikation am Client

BashTerminal — Client
$ scutil --dns | grep "nameserver\[0\]"
  nameserver[0] : ${CACHYOS_LAN_IP}

$ dig doubleclick.net +short
0.0.0.0
07
№ 07  —  TAILSCALE MAGICDNS

Globaler Nameserver im Tailnet.

Tailscale Admin Console → DNS:

  • Global Nameserver: ${TAILSCALE_IP_VPS} (Tailscale-IP des VPS, nicht Public-IP)
  • „Override local DNS": an
  • MagicDNS: bleibt an, kollidiert nicht — Tailscale-Hostnames werden direkt aufgelöst

Effekt: Tailscale-Clients bekommen den VPS-AGH als einzigen DNS, egal in welchem Netz sie hängen. Im Heim-WLAN überschreibt das den FritzBox-Eintrag. Beabsichtigt.

Verifikation am Handy

iPhone/Android mit Tailscale-App, Mobilfunk (nicht im Heim-WLAN), Tailscale aktiv:

  • Browser-Test: adblock-tester.com — erwartet ≥ 85 % Blockrate
  • App-Test: Eine App mit normalerweise viel Werbung (Wetter, Spiele) — Werbung erscheint als leere Box
08
№ 08  —  FILTERLISTEN

Vier Listen reichen.

Liste Quelle Zweck
AdGuard DNS Default adguardteam.github.io/AdGuardSDNSFilter Default
OISD Big big.oisd.nl Breit, wenig False-Positives
Hagezi Multi PRO github.com/hagezi/dns-blocklists Werbung + Telemetrie
Steven Black Hosts stevenblack.github.io/hosts Hosts-Konsolidierung

Was greift, was nicht

  • Web-Werbung: ~95 % geblockt
  • App-Telemetrie iOS/Android: ~60–80 %, abhängig von der App
  • YouTube-Pre-Rolls: nicht geblockt (gleicher Host wie das Video)
  • YouTube-Tracking-Endpoints: teilweise, betrifft Google-Empfehlungen, nicht den Ad-Auslieferer
  • Smart-TV-Telemetrie: gut abgedeckt durch Hagezi

Wenn YouTube später doch stört: SmartTube auf Android TV, ReVanced auf Android, uBlock Origin im Browser. Apple TV braucht YouTube Premium oder Magic Lasso Adblock for tvOS. Alle drei sind clientseitig und unabhängig vom AGH.

09
№ 09  —  ROLLBACK

Drei Hebel.

DNS bricht, Webseiten laden nicht. Je nach Schadensort einer der drei Eingriffe.

FritzBox-Rollback

FritzBox → Heimnetz → Netzwerk → … → Lokaler DNS-Server leeren, speichern. Heim-Clients laufen ab nächstem DHCP-Renew wieder über ISP-DNS.

Tailscale-Rollback

Tailscale Admin → DNS → „Override local DNS" abschalten und globalen Nameserver entfernen. Mobilgeräte fallen auf OS-Default-DNS.

Container-Rollback

BashVPS oder CachyOS
cd /home/admin/agh    # oder ~/.local/share/agh
docker compose stop

# Wenn nur Sync amok läuft
cd /home/admin/agh-sync
docker compose stop

Geräte fallen via Resolver-Timeout auf den nächsten konfigurierten DNS. Kostet 5–10 s pro erstem Lookup.

Reparaturen an der CachyOS-Instanz immer mit gestopptem agh-sync auf dem VPS, sonst überschreibt der nächste Sync-Lauf alle Korrekturen.

10
№ 10  —  VERIFIKATION

Sechs Checks.

BashVerifikations-Sequenz
# 1) VPS-AGH antwortet im Tailnet
dig @${TAILSCALE_IP_VPS} example.com +short
# erwartet: gültige IP

# 2) Block greift
dig @${TAILSCALE_IP_VPS} doubleclick.net +short
# erwartet: 0.0.0.0

# 3) CachyOS-AGH ist synchron
dig @${CACHYOS_LAN_IP} doubleclick.net +short
# erwartet: 0.0.0.0

# 4) eth0 ist nicht offen
dig @${VPS_PUBLIC_IP} example.com +short
# erwartet: timeout

# 5) FritzBox verteilt korrekten DNS
scutil --dns | grep "nameserver\[0\]"
# erwartet: ${CACHYOS_LAN_IP}

# 6) Mobil unterwegs (Tailscale on)
nslookup doubleclick.net
# erwartet: 0.0.0.0

Browser-Test im Inkognito-Mode auf adblock-tester.com. Erwartet: ≥ 85 % Blockrate.
