№ 01  —  INFRASTRUKTUR-PLAN STAND 20. MAI 2026

Tailnet-
Werbeblocker.

Netzwerkweites DNS-Sinkhole für alle Geräte — IoT, Smartphone, Computer, Apple TV. Zwei AdGuard-Home-Instanzen im Tailnet: VPS primär, CachyOS sekundär, synchronisiert. Ohne YouTube-Wundermittel, ohne neues Loch im VPS-Hardening.

Stand 20. Mai 2026

Geltungsbereich Heim-LAN + Tailnet
Lesedauer ≈ 12 Min.
01
№ 01  —  ÜBERSICHT

Was hier gebaut wird, und was nicht.

Ein DNS-Sinkhole auf zwei Knoten im Tailnet. Contabo VPS in Frankreich als Primary, CachyOS Desktop als Replica. Konfig und Filterlisten werden über adguardhome-sync aktiv gehalten. Mobil greift die Tailscale-App, zu Hause die FritzBox.

Das Ziel ist passive Coverage: Jedes Gerät, das ins WLAN kommt oder Tailscale aktiviert, bekommt automatisch Werbe- und Tracker-Blocking, ohne dass jemand etwas pro Gerät konfigurieren muss. Das gilt explizit auch für Klassen, die sonst durch's Raster fallen — IoT-Sensoren, Apple TV, Drucker.

Knoten2 × AGH
Syncadguardhome-sync
UpstreamQuad9 DoT
Container3 × Docker

Eine Sache ist explizit nicht im Scope: YouTube-Werbung. Pre-Rolls werden vom gleichen googlevideo.com-CDN ausgeliefert wie das Video selbst — DNS-Blocking ist dort wirkungslos. Realistische Pfade wären YouTube Premium, ReVanced/SmartTube oder Magic Lasso auf Apple TV. Der User hat sich nach Abwägung gegen alle drei entschieden und nimmt YouTube-Werbung in Kauf.

Ebenfalls draußen: ein öffentlicher DoH-Endpoint, Tailscale-Subnet-Routes ins LAN, ein eigener rekursiver Resolver, Per-Client-Familien-Filter. Alles davon ist nachziehbar, wenn die Basis steht.

Hinweis

Detail-Sektionen 03–10 sind Best-Entwurf. Die Top-Level-Architektur ist abgenickt, aber Konfig-Snippets und Werte sind noch nicht implementiert — sondern das, was nach Recherche-Stand sinnvoll ist. Beim Setup pro Sektion noch einmal sortieren.

02
№ 02  —  ARCHITEKTUR

Zwei Knoten, ein Tailnet, drei Datenflüsse.

VPS-AGH ist die einzige Bedienoberfläche. CachyOS-AGH ist passiver Spiegel. FritzBox und Tailscale verteilen den DNS-Server an die Endgeräte.

Die drei Datenflüsse

Pfad Auslöser Resolver Upstream
Heim-LAN / IoT FritzBox-DHCP CachyOS-AGH (LAN-IP) Quad9 DoT
Mobil unterwegs Tailscale-App + MagicDNS VPS-AGH (Tailscale-IP) Quad9 DoT
Mobil zu Hause (Tailscale on) Tailscale "Override local DNS" VPS-AGH (Tailscale-IP) Quad9 DoT

Single Source of Truth

Bedienung läuft immer über das VPS-AGH-Web-UI. Die CachyOS-Instanz ist ein passiver Spiegel — Änderungen dort werden beim nächsten Sync-Lauf überschrieben. Diese Strikt­heit ist gewollt: kein „kurz hier was eingestellt, vergessen, später widersprüchlich".

Tipp

Wenn die CachyOS-UI muckt (Sync-Fehler, falsche Listen): immer zuerst adguardhome-sync stoppen, bevor du händisch reparierst. Sonst läuft dir der Sync in die Reparatur rein.

03
№ 03  —  VPS-AGH (PRIMARY)

Tailscale-only Bind, kein Loch in eth0.

AGH läuft als Docker-Container, gebunden ausschließlich an die Tailscale-IP. Das VPS-Hardening bleibt unangetastet — kein neuer Public-Port, keine UFW/nftables-Anpassung.

Bind-Strategie

Docker bindet die Ports so an die Tailscale-IP, dass sie nur aus dem Tailnet erreichbar sind. 0.0.0.0 ist verboten — beim Compose-File explizit darauf achten.

YAML/home/admin/agh/docker-compose.yml
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: agh-primary
    restart: unless-stopped
    ports:
      # DNS — NUR auf Tailscale-IP
      - "${TAILSCALE_IP_VPS}:53:53/udp"
      - "${TAILSCALE_IP_VPS}:53:53/tcp"
      # Web-UI — ebenfalls Tailnet-only
      - "${TAILSCALE_IP_VPS}:3000:3000/tcp"
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf
    network_mode: bridge
Warnung

Wenn Docker auf network_mode: host umgestellt wird (z.B. für IPv6-DNS), umgeht das den IP-Bind und exponiert Port 53 auf allen Interfaces — inklusive eth0. Niemals ohne explizite UFW-Regel deny 53/udp on eth0.

Upstream

Quad9 mit DoT als Primary (Malware-Blocking inklusive). Cloudflare DoT als Fallback. Kein UDP-Fallback auf ungesichertes DNS.

YAMLconf/AdGuardHome.yaml (excerpt)
dns:
  upstream_dns:
    - tls://dns.quad9.net
    - tls://1.1.1.1
  upstream_mode: parallel
  fastest_addr: true
  cache_size: 8388608
  cache_ttl_min: 600
  ratelimit: 0      # Tailnet-only, kein Rate-Limit nötig
  bootstrap_dns:
    - 9.9.9.9
    - 1.1.1.1
04
№ 04  —  CACHYOS-AGH (REPLICA)

Lokal für IoT, Tailnet für mobil.

Zweite AGH-Instanz auf dem Desktop. Bedienung aus — nur Spiegelbild des VPS. Bindet auf LAN-IP (für FritzBox-Clients) und Tailscale-IP (für Tailnet-Geräte zu Hause).

Bind-Strategie

Drei Bind-Adressen: LAN für IoT, Tailscale für Mobil, Loopback als Sicherheitsnetz gegen lokale DNS-Tools, die Public-Resolver verwenden würden.

YAML~/.local/share/agh/docker-compose.yml
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: agh-replica
    restart: unless-stopped
    network_mode: host      # nötig für mehrere IPs
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf

Mit network_mode: host bindet AGH selbst — die Bind-Adressen werden in der AGH-Konfig festgelegt:

YAMLconf/AdGuardHome.yaml (excerpt)
dns:
  bind_hosts:
    - ${CACHYOS_LAN_IP}
    - ${TAILSCALE_IP_CACHYOS}
    - 127.0.0.1
  port: 53
Hinweis

Auf CachyOS belegt systemd-resolved standardmäßig Port 53 auf 127.0.0.53. Falls Konflikt: DNSStubListener=no in /etc/systemd/resolved.conf, dann systemctl restart systemd-resolved.

05
№ 05  —  ADGUARDHOME-SYNC

Master pusht, Replica empfängt.

Sync-Container läuft auf dem VPS, pollt alle 5 Minuten das eigene AGH-API und überträgt Diffs an die CachyOS-Replica per HTTPS+API-Token.

YAML/home/admin/agh-sync/docker-compose.yml
services:
  agh-sync:
    image: ghcr.io/bakito/adguardhome-sync:latest
    container_name: agh-sync
    restart: unless-stopped
    env_file: ./.env
    command: run
ENV/home/admin/agh-sync/.env (chmod 600)
ORIGIN_URL=http://${TAILSCALE_IP_VPS}:3000
ORIGIN_USERNAME=admin
ORIGIN_PASSWORD=<secret>
REPLICA1_URL=http://${TAILSCALE_IP_CACHYOS}:3000
REPLICA1_USERNAME=admin
REPLICA1_PASSWORD=<secret>
CRON=*/5 * * * *
RUN_ON_START=true
FEATURES_FILTERS=true
FEATURES_CLIENTS=true
FEATURES_DNS_SERVER_CONFIG=true
FEATURES_DNS_REWRITES=true

Der Sync-Container braucht selbst keinen Port nach außen. Er nutzt nur ausgehende Verbindungen zum Tailnet — also durch die Tailscale-Schnittstelle.

06
№ 06  —  FRITZBOX 7520

Ein Feld, alle Geräte.

Die FritzBox verteilt einen einzigen DNS-Wert per DHCP an alle Clients im Heim-Netz, inklusive IoT, Apple TV und Drucker. Eintrag in der Box, fertig.

Pfad in der UI

FritzBox-Webinterface (http://fritz.box) → Heimnetz → Netzwerk → Netzwerkeinstellungen → IP-Adressen → IPv4-Konfiguration → unter „Heimnetz" das Feld „Lokaler DNS-Server" auf ${CACHYOS_LAN_IP} setzen.

Wirksamkeit beschleunigen

Clients ziehen den neuen DNS erst beim nächsten DHCP-Renew. Schnellster Pfad:

  1. DHCP-Lease-Zeit kurzfristig auf 5 Minuten senken (gleiche Seite, weiter unten).
  2. Alle Geräte einmal aus dem WLAN nehmen und wieder hinein (oder neu booten).
  3. Lease-Zeit zurück auf 24 Stunden, sobald alles läuft.

Verifikation am Client

Auf einem MacBook im WLAN:

BashTerminal — Client
$ scutil --dns | grep "nameserver\[0\]"
  nameserver[0] : ${CACHYOS_LAN_IP}

$ dig doubleclick.net +short
0.0.0.0      # Block durch AGH
Limit

Das Gäste-WLAN ignoriert den lokalen DNS-Eintrag — die FritzBox setzt sich dort immer selbst als DNS. Für Besucher meist egal, aber wenn das eigene Telefon im Gäste-Netz hängt, läuft es ohne AGH. Lösung im Bedarfsfall: Tailscale auf dem Telefon einschalten.

07
№ 07  —  TAILSCALE MAGICDNS

Globaler Resolver, überall identisch.

Im Tailscale-Admin-Panel den VPS-AGH als globalen Nameserver eintragen. „Override local DNS" an. Jedes Mobilgerät blockt dann unterwegs genauso wie zu Hause.

Admin Console → DNS

Global nameserverrequired
${TAILSCALE_IP_VPS} — die Tailscale-IP des VPS-Knotens, nicht die Public-IP. Ist eingetragen in Tailscale-Admin → DNS → „Add nameserver".
Override local DNSboolean, true
Setzt den AGH als einzigen DNS auf allen Tailscale-Clients, auch wenn das WLAN einen eigenen DNS verteilt. Verhindert Leak in fremde Resolver
MagicDNSboolean, true
Bleibt aktiv — kollidiert nicht mit dem globalen Nameserver, weil Tailscale Tailnet-Hostnamen direkt auflöst, ohne durch AGH zu gehen.

Verifikation am Handy

iPhone/Android mit Tailscale-App, Mobilfunk (nicht im Heim-WLAN), Tailscale aktiv:

  • Browser-Test: d3ward.github.io/toolz/adblock.html sollte ≥ 85 % Block-Rate zeigen.
  • App-Test: Eine App, die normalerweise viel Werbung zeigt (Wetter-App, Spiele-App), öffnet die Werbung als leere Box.
№ 07.5 — HALTUNG
Ein Werbeblocker, der nur am Schreibtisch funktioniert, hat genau dort versagt, wo er gebraucht wird. — Begründung für den Tailnet-Pfad
08
№ 08  —  FILTERLISTEN

Vier Listen, ein realistischer Erwartungshorizont.

Mehr Listen heißt nicht mehr Blocking — heißt mehr False-Positives. Diese Auswahl deckt ~95 % der klassischen Werbung ab, ohne dass legitime Seiten brechen.

Liste Quelle Zweck
AdGuard DNS Default adguardteam.github.io/AdGuardSDNSFilter Werbung + Tracker (Default)
OISD Big big.oisd.nl Werbung breit, low False-Positive
Hagezi Multi PRO github.com/hagezi/dns-blocklists Werbung + Telemetrie, inkl. Smart-TV
Steven Black Hosts stevenblack.github.io/hosts Klassische hosts-Konsolidierung

Was tatsächlich blockt — und was nicht

  • Klassische Web-Werbung: ~95 % geblockt.
  • App-Telemetrie auf iOS/Android: ~60–80 %.
  • YouTube-Pre-Rolls: nicht geblockt. Werbung kommt vom gleichen googlevideo.com-CDN wie das Video — DNS kann nicht differenzieren.
  • YouTube-Tracking-Endpoints: teilweise geblockt — bricht Google-Empfehlungs-Statistik, nicht den Ad-Auslieferer.
  • Smart-TV-Telemetrie: stark geblockt durch Hagezi (LG, Samsung, Sony, Vizio-Listen).
YouTube

Falls die YouTube-Werbung später doch stört: clientseitige Lösungen pro Plattform — SmartTube auf Android TV, ReVanced auf Android, uBlock Origin im Browser. Apple TV bleibt ohne YouTube Premium oder Magic Lasso Adblock for tvOS außen vor. Diese Erweiterungen sind kompatibel mit dem AGH-Setup, brauchen aber jeweils eigenen Wartungsaufwand.

09
№ 09  —  ROLLBACK & NOTFALL

Drei Hebel, drei Sekunden bis offline ist es nicht.

Wenn DNS bricht und Webseiten nicht mehr laden: drei Eingriffsstellen, je nach Schadensquelle. Jede einzelne setzt das Heim wieder auf den ISP-DNS zurück.

FritzBox-Rollback (Heim-LAN sofort)

FritzBox → Heimnetz → Netzwerk → … → Lokaler DNS-Server leeren, speichern. Heim-Clients laufen ab nächstem DHCP-Renew wieder über ISP-DNS. Sofort-Effekt via Lease-Verkürzung.

Tailscale-Rollback (Mobil-Geräte)

Tailscale Admin → DNS → „Override local DNS" abschalten und globalen Nameserver entfernen. Mobilgeräte fallen auf OS-Default-DNS (Mobilfunk-Resolver oder fremdes WLAN).

Container-Rollback (Resolver tot)

BashVPS oder CachyOS
# Notfall-Stop
cd /home/admin/agh    # oder ~/.local/share/agh
docker compose stop

# Wenn nur Sync amok läuft
cd /home/admin/agh-sync
docker compose stop

Geräte fallen via Resolver-Timeout auf den nächsten konfigurierten DNS zurück. Unangenehm (5–10 s pro erstem Lookup), aber überlebbar.

Sync vor Reparatur stoppen

Bei Reparaturen an der CachyOS-Instanz immer zuerst agh-sync auf dem VPS stoppen. Sonst überschreibt der nächste Sync-Lauf alle Korrekturen mit dem alten VPS-Stand.

10
№ 10  —  VERIFIKATION

Sechs Befehle, alles grün.

Sequenzielle Checks. Wenn einer rot ist, weitergehen ist sinnlos — erst Wurzel finden.

BashVerifikations-Sequenz
# 1) VPS-AGH antwortet im Tailnet
dig @${TAILSCALE_IP_VPS} example.com +short
# erwartet: gültige IP

# 2) Block greift auf VPS-AGH
dig @${TAILSCALE_IP_VPS} doubleclick.net +short
# erwartet: 0.0.0.0

# 3) CachyOS-AGH ist synchron
dig @${CACHYOS_LAN_IP} doubleclick.net +short
# erwartet: 0.0.0.0

# 4) eth0 ist DICHT (vom Internet aus)
dig @${VPS_PUBLIC_IP} example.com +short
# erwartet: timeout — NICHT eine IP

# 5) FritzBox verteilt korrekten DNS
scutil --dns | grep "nameserver\[0\]"
# erwartet: ${CACHYOS_LAN_IP}

# 6) Mobil unterwegs (Tailscale on, Mobilfunk)
nslookup doubleclick.net
# erwartet: 0.0.0.0

Anschließend Browser-Test auf d3ward.github.io/toolz/adblock.html — im Inkognito-Mode, damit Browser-Extensions nicht mit-blocken. Erwartung: ≥ 85 % Block-Rate.
